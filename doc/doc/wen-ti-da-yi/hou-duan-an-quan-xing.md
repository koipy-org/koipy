# 后端安全性

## bot与后端的工作方式

koipy 完整实现了miaospeed的对接协议。

它会先在本地把订阅解析成节点列表，然后把这些节点写进发往后端的请求体，再通过 WebSocket 协议发送出去。

也就是说，bot 到后端这条链路上传输的内容，至少包括：

1. 订阅解析后的节点信息
2. 本次测速使用的任务参数
3. 用于后端校验的签名字段 `Challenge`
4. 后端返回的测试结果

所以这条链路一旦被窃听，泄露的不只是“测速结果”，而是整批待测节点的元数据。

## 后端签名校验

koipy 连接 MiaoSpeed 后端时，会实行对请求体的签名。

当前版本中，每次发请求前都会基于：

1. 后端 `token`
2. `buildtoken`
3. 当前请求体（内部程序对象）序列化

生成签名，并把签名写进 `Challenge` 字段发送给后端。

这意味着：

1. 只知道后端地址和路径，不足以伪造一个合法请求
2. 后端可以用共享密钥校验请求是否被合法客户端（主端）生成
3. `token` 泄露后，这层保护基本就失效了

但要注意，签名解决的是“认证”问题，不解决“保密”问题。

## 中间人攻击会导致订阅泄露

关键点在于：订阅内容已经被展开成节点列表，并实际出现在 bot 发给后端的报文里。

如果连接方式是 `ws://`，路径上的中间人可以直接看到明文请求，自然也就能拿到整份节点列表。

如果连接方式是 `wss://`，但你把 `skipCertVerify=true` 打开，那么主动中间人仍然可能伪造证书，把这条连接劫持下来，再在中间解密和转发流量。

这时会发生什么：

1. bot 认为自己连上了“后端”
2. 中间人拿到完整请求体
3. 中间人看到其中的节点列表、测速参数和签名字段
4. 中间人再把请求转发给真实后端
5. 整个测速表面上看起来还能正常完成

这就是最危险的地方：用户往往只看到“结果能出图”，却意识不到订阅已经在链路上被旁路复制了一份。

## “订阅”泄露了什么

这里说的订阅泄露，不是原始订阅 URL 泄露，koipy已经提前处理过了，订阅链接永远不会发送到后端。

而是以下内容泄露：

1. 订阅中所有节点的服务器地址和端口
2. 节点协议类型和关键连接参数
3. 节点备注名与分组信息
4. 订阅里附带的 DNS 配置

对很多人来说，这已经等价于“订阅内容泄露”了，因为攻击者拿到这些信息后，往往已经足够：

1. 复刻你的节点清单
2. 分析你的线路来源和供应商
3. 针对特定节点做限速、封锁或探测

## 哪些配置最危险

从行为看，下面两种配置风险最高：

1. `tls=false`
2. `tls=true` 但 `skipCertVerify=true`

对于非本地（经过公网传输）的后端，这两种都不应视为安全配置。

`path` 自定义、`token` 足够复杂当然也有价值，但它们不能替代 TLS 证书校验：

1. `path` 用来降低被爬虫随手扫到的概率
2. `token` 用来防止伪造请求
3. 真正防止中间人偷看内容的，仍然是正确校验证书的 `wss://`

## 实际建议

如果你的后端不是跑在同个机器或完全可信的内网里，至少做到下面这些：

1. 使用 `tls=true`
2. 尽量保持 `skipCertVerify=false`
3. 每个后端使用独立 `token`
4. 不要长期使用默认根路径
5. 能放到 VPN、内网穿透专线或 SSH 隧道里，就不要直接裸露到公网
6. 如有必要，请进行VPN组网（Wireguard、Tailscale、easytier等）

## mTLS 与反向连接

v2.1.0 起新增了两种连接方式，它们的安全含义与普通连接不同：

### mTLS 双向证书认证

普通 `wss://` 只解决主端验证后端，后端并不验证主端。开启 `mtls` 后，双方都要出示证书：

* 主端（koipy）通过 `clientCertFile` 提供客户端证书
* 后端（miaospeed）默认通过系统根证书（CA）校验客户端证书，但是你可以在后端启动的参数加上 `-clientca` 来让后端使用指定的CA校验客户端证书，这对于自签CA的场景尤其有用

这样做的好处是，即使 `token` 泄露，攻击者没有可信客户端证书也无法伪装成主端向后端下发任务。

{% hint style="warning" %}
koipy 不信任系统根证书，而是使用自己携带的 CA 证书。后端若使用自签名证书，需要通过 `caCertFile` 显式把它加入信任列表，否则连接会失败。
{% endhint %}

### 反向连接

反向连接是为了解决后端位于 NAT 后方、主端无法主动访问的场景。此时由后端主动连接 koipy，链路方向与普通模式相反。

需要特别注意两点：

1. 反向连接**没有 IP 白名单**，`token` 是唯一的门禁。也就是说，只要知道监听地址与 `token`，任何人都能连接进来
2. 因此当 `reverseListen` 监听在公网地址时，**务必开启 `reverseTLS`**，否则节点信息会在链路上明文传输

{% hint style="danger" %}
反向连接在 `reverseTLS=false` 且监听公网的情况下，等同于把 `ws://` 直接暴露出去：任何嗅探到链路的人都能拿到完整的节点列表。请不要在这种配置下传输真实订阅。
{% endhint %}
